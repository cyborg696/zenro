# ZENRO Wrist & Co. — online watch store

The website of **ZENRO Wrist & Co.** (logo: ZENRO WRIST), an online watch seller from Chandpur, Bangladesh, established in 2026.

- **Cash on Delivery all over Bangladesh.** Customers can also pay by bKash, Nagad, Rocket or bank transfer.
- **Orders arrive on WhatsApp** (01960520872).
- Instagram: <https://www.instagram.com/zenro_wrist_co/> · Facebook: <https://www.facebook.com/profile.php?id=61594772414204>

The site is plain **HTML, CSS and JavaScript**: no framework, no build step. It runs free on **GitHub Pages**.

## What the site does

| Page | File | What it does |
| --- | --- | --- |
| Home | `index.html` | Hero with a watch that shows the live Bangladesh time (UTC+6), featured watches, "Shop by brand", why ZENRO, how to order, customer reviews (only when you add real ones), Instagram and Facebook links |

| Checkout | `checkout.html` | Delivery details, delivery zone, payment method, review |
| Order confirmation | `order-confirmation.html` | Asks the customer to **send the order on WhatsApp**. The order is not confirmed until you receive that message |

| Contact | `contact.html` | WhatsApp, Instagram, Facebook. The form prepares a WhatsApp message |

**Placeholders are never shown as real information.** Anything you have not filled in yet is still `TODO_OWNER`. The site hides it or shows "Ask us on WhatsApp" instead.

## Adding a brand, a model and a watch

Everything is in **`js/products.js`**. After you save, every page (menu, shop, product pages, footer) updates automatically.

Slugs and ids may only contain lowercase letters, numbers and hyphens, because they are used in links.

**1. Add a brand** (skip this if the brand already exists):

```js
{ slug: 'cartier', name: 'Cartier', order: 5, intro: 'TODO_OWNER' },
```

**2. Add a model** (sub-branch) under that brand:

```js
{ slug: 'santos', brand: 'cartier', name: 'Santos' },
```

**3. Add the watch** to `PRODUCTS`:

```js
{
  id: 'cartier-santos-01',        // unique; becomes product.html?id=cartier-santos-01
  brand: 'cartier',
  model: 'santos',
  name: 'Cartier Santos',
  variant: 'Silver dial, steel bracelet',  // or 'TODO_OWNER'
  price: 12500,                   // Taka, whole number. null = "Ask for price"
  compareAtPrice: null,           // an old, higher price shows a "Sale" badge
  inStock: true,                  // false = "Sold out" + "Notify me on WhatsApp"
  featured: false,                // true = shown on the home page
  condition: 'TODO_OWNER',        // must be one of the labels in config.js → conditions
  images: [],                     // paste the lines printed by the photo tool
  instagramUrl: 'https://www.instagram.com/zenro_wrist_co/p/XXXXXXXX/',
  description: 'Short honest description.',
  specs: { caseSize: null, caseMaterial: null, movement: null, dial: null, strap: null, waterResistance: null, crystal: null },
},
```

- Specs left as `null` are not shown.
- Watches with `price: null` cannot be added to the cart. They show "Ask for price on WhatsApp".
- Do not call a watch genuine, authentic or original anywhere unless you set `condition: 'Original'` for it.
- Never add a watch brand's logo or crown/emblem artwork. Brand names are plain text only.
- Then run `npm run stamp` to add the new brand, model and product links to `sitemap.xml`.

## Adding product photos

1. Install [Node.js](https://nodejs.org/) (version 18 or newer). Then, in the project folder, run this once:
   ```bash
   npm install
   ```
2. Copy your photos into `images/raw/` and name them `<product-id>-<n>.jpg`. For example:
   - `images/raw/rolex-datejust-01-1.jpg`
   - `images/raw/rolex-datejust-01-2.jpg`

   PNG also works. The product id must already exist in `js/products.js`.
3. Run:
   ```bash
   npm run images
   ```
   For every photo, the tool:
   - turns it the right way up
   - **removes all EXIF and GPS location data**
   - crops it to 4:5 (use `node tools/optimise-images.mjs --contain` to pad instead of crop, or `--studio` for phone / Instagram photos: tone and colour correction, sharpening, and a blurred dark backdrop instead of black bars; or `--lowkey` for a premium dark spotlight look, positions in `tools/photo-focus.json`)
   - saves a 1200 px and a 600 px WebP in `images/products/<brand>/<model>/`
   - never enlarges a small photo: a 640 px source gives a 640 px large file named `...-w640.webp` (the site reads the width from the name)
4. The tool prints lines like `images: ['images/products/rolex/datejust/rolex-datejust-01-1.webp', ...]`. Paste each one into its product in `js/products.js`.

Until a watch has photos, it shows a dark "ZENRO" card with its name. The originals in `images/raw/` are listed in `.gitignore`, so they are never uploaded.

## Demo mode (client previews)

`demoMode: true` in `js/config.js` turns on sample data from `js/demo-data.js`, so the whole shop can be clicked through before the real prices and payment numbers are known. Nothing fake is written into `config.js` or `products.js`: the samples only fill settings that are still `TODO_OWNER`, and a real value always wins.

While demo mode is on:

- every page shows a gold "Demo preview. Prices and payment details are samples. Please do not send money." banner
- sample prices (and sample delivery charges) carry a **Sample** tag, and products without a condition show "Sample listing"
- payment panels show `01XXXXXXXXX` (bank: "Demo Bank Ltd", `0000000000000`) with "Demo number. Do not send money." and no Copy button
- order IDs start with `ZW-DEMO-` and the WhatsApp message starts with "DEMO ORDER (not real, no payment made)"
- product pages carry no price in their search-engine data (JSON-LD)
- **`npm run stamp` adds `<meta name="robots" content="noindex">` to every page, so search engines do not index the sample prices**

**Before launch:** set `demoMode: false` in `js/config.js`, run `npm run stamp` (this removes the noindex tags again), run `npm test`, then commit and push. With `demoMode: false`, `js/demo-data.js` has no effect at all.

## Filling in `js/config.js`

Open `js/config.js`. Every setting has a comment. Replace each `TODO_OWNER` with the real value:

| Setting | Example | What happens while it is still `TODO_OWNER` |
| --- | --- | --- |
| `siteUrl` | `'https://zenrowrist.com/'` | Link previews, `sitemap.xml` and `robots.txt` use a placeholder address. Run `npm run stamp` after setting it |
| `delivery.insideDhaka` / `outsideDhaka` | `80`, `130` | Delivery shows "Confirmed on WhatsApp" |
| `delivery.estimatedDays` | `'1–2 days inside Dhaka, 2–4 days outside'` | "Ask us on WhatsApp" |
| `cod.advanceRequired` | `0`, `'deliveryCharge'` or `500` | No advance is asked for |
| `payments.bkash/nagad/rocket` | `number: '01XXXXXXXXX', accountType: 'Merchant'` or `'Personal'` | That method is hidden at checkout |
| `payments.bank` | bank name, account name, account number (branch and routing are optional) | Bank transfer is hidden |
| `paymentLogos` | `{ bkash: 'images/payments/bkash.svg' }` (only official files you may use) | Method names are shown as coloured text |
| `conditions` | `['Original', 'Pre-owned', 'Homage / Inspired design']` | No condition badges are shown. Products say "Condition: ask us on WhatsApp" |
| `warranty`, `returnPolicy` | short text | Hidden in the footer and on product pages. The returns page shows "Ask us on WhatsApp" |
| `aboutStory` | a paragraph | Hidden on the About page |
| `priceRanges` | `[5000, 10000, 20000]` | Used for the shop price filter |
| `reviews` | `{ name, city, text, image }` | The reviews section is hidden. Only add reviews you have permission to publish |

**Never put passwords, PINs, API keys or merchant secrets in `config.js`.** Anyone can read it.

## How orders reach you

1. The customer completes checkout. The order is checked again, then saved only in their browser tab. It is never put in a link.
2. The confirmation page shows a large **Send order on WhatsApp** button. This opens WhatsApp with a ready-made message to `01960520872` containing:
   - the order ID (`ZW-YYMMDD-XXXX`)
   - the items, prices and total
   - the customer's name, phone and address
   - the payment method, sender number and TrxID
3. The cart is cleared only after the customer taps that button. If they try to leave first, a reminder banner appears once.
4. For bKash, Nagad, Rocket and bank payments, check the TrxID or reference in your account before you confirm. Bank customers are asked to send the deposit slip photo in the chat.

**Optional second copy:** set `orderWebhookUrl` in `config.js`. Each order is then also sent to a form service:

- **Formspree** is the simplest option. Set `webhookAllowedOrigins: ['https://formspree.io']`, then run `npm run stamp` to allow it in the page's Content-Security-Policy.
- **Google Apps Script** writes each order to a Google Sheet. It needs **both** `https://script.google.com` and `https://script.googleusercontent.com` in `webhookAllowedOrigins`. Run `npm run stamp` afterwards. The site sends Apps Script requests as `text/plain`, which avoids a CORS preflight.

Full steps are in [docs/PAYMENT_GATEWAY.md](docs/PAYMENT_GATEWAY.md).

## Updating the header, footer or site address

All pages share the same `<head>` tags, header, footer and floating WhatsApp button. These shared parts are defined once, in `tools/stamp.mjs`. Each page's own content, inside `<main id="main">…</main>`, stays in its HTML file, and you can edit it there directly.

Run the stamper after any of these changes:

- the header, footer, menu, social links, page titles or descriptions, scripts or Content-Security-Policy (edit `tools/stamp.mjs`)
- `siteUrl` in `js/config.js`
- adding or removing brands, models or watches in `js/products.js` (this keeps `sitemap.xml` up to date)

```bash
npm run stamp
```

The stamper needs Node.js, but not `npm install`. It rewrites the shared parts of every page and regenerates `sitemap.xml` and `robots.txt`. Do not edit the header or footer directly in the HTML files, because the next stamp overwrites those edits.

It also adds any `webhookAllowedOrigins` from `js/config.js` to `connect-src` on `order-confirmation.html`, and only on that page, so you never edit the CSP by hand.

## Run it on your computer

Serve the folder over HTTP. Opening the files directly will not work because of the security policy and browser storage:

```bash
python -m http.server 8000     # or: npx serve .
```

Then open <http://localhost:8000>.

## Deploy on GitHub Pages

1. Push this folder to a GitHub repository. `node_modules/` and `images/raw/` are ignored automatically.
2. On GitHub, open **Settings → Pages**. Choose **Deploy from a branch**, select `main` and `/ (root)`, then click **Save**.
3. After a minute the site is live at `https://<username>.github.io/<repo>/`, or at your own domain if you set one up.
4. Set `siteUrl` in `js/config.js` to the live address, run `npm run stamp`, then commit and push the changed files. This updates:
   - `sitemap.xml`
   - `robots.txt`
   - the `og:url` / `og:image` tags in each page's `<head>`

   Facebook and WhatsApp link previews need the full address.

All links are relative, so the site also works from a sub-folder. Search engines only read `robots.txt` at the root of a domain. On a `username.github.io/<repo>/` address it has no effect, but the `noindex` tags on the cart, checkout and confirmation pages still work.

## Online payments later (Phase B)

Right now payments are checked by hand (Phase A). To take payments online, use either:

- **SSLCommerz** (one integration for bKash, Nagad, Rocket, cards and internet banking), or
- **bKash Tokenized Checkout**.

Either one needs a merchant account and a small server or serverless function that keeps the secrets and **verifies every payment on the server**. The browser is never trusted to say a payment succeeded. The site already has a payment provider interface ready for this. See [docs/PAYMENT_GATEWAY.md](docs/PAYMENT_GATEWAY.md).

## Quality and security

**Security**
- Strict Content-Security-Policy on every page: no inline scripts, no `eval`, scripts only from this site.
- No `innerHTML`: all content is built with `createElement` and `textContent`.
- Every input is sanitised and length-limited. Control characters, invisible characters and angle brackets are removed. Bangladeshi mobile numbers must match `01[3-9]XXXXXXXX` after `+88` is removed. TrxIDs must be 6–20 letters or digits.
- Every URL value and everything read from browser storage is checked against the catalogue or a fixed list. Cart prices are always recalculated from `products.js`.
- Honeypot fields on the checkout and contact forms, and a limit of one order every 30 seconds.

**Accessibility**
- One `h1` per page and labelled fields. Errors are linked to their fields, and focus moves to the first error.
- Live regions for status messages, visible focus outlines, and keyboard-only checkout.
- Reduced-motion support.

**Performance and SEO**
- Lazy-loaded WebP photos with fixed sizes. No frameworks.
- Open Graph tags, `sitemap.xml`, and JSON-LD product data (`priceCurrency: "BDT"`) from a separate script file.
